# 個人効率システム · ユーザーガイド（日本語）

このガイドは「日次実行 → 週次レビュー → 月次リファクタ」の循環を実践するためのものです。4 つの実装はデータモデルを共有し、Django／Spring Boot／Gin は PC・モバイル画面、FastAPI は Vue 3 のレスポンシブ画面と REST API を提供します。

- [简体中文](user_guide.md) · [English](user_guide.en.md) · [繁體中文](user_guide.zh-TW.md)
- [プロジェクト README に戻る](../README.md)

## 1. ログインと PC／モバイルの切り替え

1. 使いたい版のルート URL を開きます（Django `http://127.0.0.1:8000/`、Spring Boot `:8080/`、Gin `:8081/`、FastAPI はフロントエンドのビルド後に `:8000/`）。アカウントとパスワードでログインします。
2. **Django／Spring Boot／Gin のデュアルビュー**：サーバーがブラウザの User-Agent で PC 版／モバイル版を自動選択します。スマートフォンではタッチ操作に適した画面になります。
3. **最初の 3 版の手動切り替え**：
   - PC 版の上部バー「📱 モバイル」でモバイル版へ；
   - モバイル版のヘッダー「🖥 PC」で PC 版へ戻ります。下部バーに「自動」もあり、端末判定に戻せます。
   - 選択はブラウザの Cookie（有効期限 1 年）に保存され、次回開いたときも維持されます。
   - 切り替えると現在のページが再読み込みされます。未保存のフォーム入力は失われるため、切り替える前に保存してください。

4. **FastAPI の画面**：PC とスマートフォンで同じ Vue 3 のレスポンシブ画面を使います。スマートフォンではナビゲーションがメニューに折りたたまれます。画面は FastAPI と同じオリジンから配信され、`/docs` は対話型 API ドキュメントです。

## 2. 毎日の実行チェックリスト（朝 3 分＋夜 5 分）

「日次実行」から「今日のリストを作成」を開きます。画面は 5 つのセクションです。

1. **今日の方向**：日付、睡眠時間、精力（低／中／高）を入力し、**今日最も重要な成果（MIT）**を書きます。成果を先に決め、その後に時間を割り当てます。
2. **ブロックとタイムボックス**：2〜4 個のブロックそれぞれに「名前、開始／終了時刻、入力、重要アクション、検収可能な成果」を記入します。終了時に進捗を確認するだけで、無理に完遂する必要はありません。完了をチェックできます。
3. **実行前後のチェック**：開始前 3 項目（成果を知っている／材料準備済み／通知対応済み）、実行中 3 項目（一度に一ブロック／詰まったら次の一歩を小さく／妨害を記録）、終了後 3 項目（目に見える成果／能動的回想／次の一歩を記録）。
4. **生活の維持**：水分と食事、運動、清掃・整理、実際の交流や屋外——満点を目指さず、基本盤を保ちます。
5. **夜のレビュー**：今日本当に達成したこと、最大の抵抗、明日の最小の一歩、感謝したこと。

保存後、一覧に各日のブロック進捗（完了数／総数）とチェック達成度が表示されます。Django では一覧からブロックの完了状態を切り替えられます。Gin と Spring Boot では編集フォームで完了状態を変更します。3 版とも記録の編集・削除ができます。

**要点**：MIT は 1 つだけ。各ブロックには検収可能な成果が必要。夜のレビューは「計画」ではなく「実際に達成したこと」を問います。

## 3. 毎週のレビューチェックリスト（週 30〜45 分）

「週次レビュー」から「今週のレビューを作成」を開きます。4 つのセクションです。

1. **今週の振り返り**：仕事／プロジェクト、学習／スキル、身体／精力、関係／生活の 4 領域について、**感覚ではなく事実**で成果を書き、状態（順調／阻塞／停止）を付けます。
2. **タスクフローの整理**：タスクを「未着手／進行中／完了／削除・委譲・延期」の 4 列に分けます。大事なのは出口を用意すること。溜め込むだけにしないでください。
3. **来週の設計**：来週の最重要成果は最大 1〜3 件、守るべき集中時間（日時／時間帯）、事前に準備する環境や材料、そして If–Then プラン（「もし…なら、私は…する」）。
4. **レビュー設問**：どのブロックが上達したか、時間をかけたが価値が低かったことは何か、見積もりが最も外れたタイムボックスはどれか、休息・喜び・実際のつながりはあったか、来週続ける／調整する／やめることは何か。

**要点**：週次レビューは週次計画より重要です。目的は予定を詰め込むことではなく、来週をより明確に、軽く、効果的にすることです。

## 4. 毎月のリファクタチェックリスト（月 45〜60 分）

「月次リファクタ」から「今月のリファクタを作成」を開きます。4 つのセクションです。

1. **目標と価値のチェック**：今月の最重要成果、まだ投資する価値があるか（はい／調整／停止＋理由）、今月最も価値ある投資、今月最大の機会費用。
2. **システム健全性チェック**：方向の明確さ、タスク負荷／進行中作業、ブロック品質、タイムボックスの現実性、睡眠・体力・感情、レビューとフィードバックの質の 6 モジュールに 1〜5 点を付け、必要な変更を書きます。ダッシュボードに平均点が表示されます。
3. **来月の 3 つの改善**：「残す（効いているもの）」「削る（低価値なもの）」「試す（新しい最小の変化）」の 3 つだけ。
4. **四半期の方向調整**（任意）：スキルが作品になっているか、仕事が長期方向に近づいているか、生活の主体性が高まっているか、回復と人間関係への投資は十分か、長期投資を続ける／転換する／やめるべきか。

**要点**：最終基準は——大切なことが着実に進み、生活の基本盤が安定し、注意力に主体性があり、システム自体が負担にならないことです。

## 5. 4 版の説明とデータ共有

Django / Spring Boot / Gin / FastAPI の 4 版は同じデータベースとテーブルを共有し、データはアカウントごとに分離されます。FastAPI は Spring Boot / Gin と API Token 契約を共有し、画面版はそれぞれ異なるセッション方式を使います。

- **画面ユーザー**：Session／署名付き Cookie でログイン。データはアカウントごとに分離され、他人のリストは見えません。
- **FastAPI の画面／API ユーザー**：画面ログイン後、ブラウザが現在のセッション Token を保持します。API 呼び出しでは `POST /api/auth/login` で Token を取得し、`Authorization: Bearer <token>` で送信します。FastAPI、Spring Boot、Gin 間で Token を共有できます。詳細は [API 契約](../db/API.md)。
- 既定ポート：Spring Boot 8080、Gin 8081、FastAPI 8000。Django と FastAPI はどちらも 8000 なので、同時起動時はずらしてください。

## 6. よくある質問

**Q：モバイル／PC を切り替えるとデータは消えますか？**
いいえ。切り替えは表示テンプレートとブラウザ設定を変えるだけで、データは変わりません。未保存の入力は自動保存されないので、離れる前に保存してください。

**Q：同じ日／週／月に複数件登録できますか？**
できません。（アカウント、日付／週／月）に一意制約があり、1 日 1 件、1 週 1 件、1 か月 1 件です。変更する場合は既存の記録を編集してください。

**Q：明細項目（タイムボックス、領域、タスクフロー、健全性）はどう保存されますか？**
親のリストと一緒に保存されます。編集で明細行を変更して保存すると、古い明細がまとめて置き換わります。各項目を個別に保存する必要はありません。

**Q：忘れた日のデータを追加入力したい場合は？**
日次実行の一覧から「今日のリストを作成」を開き、過去の日付を選べば登録できます。その日に既に記録がある場合は編集してください。

**Q：スマートフォンで内容が読みにくいです。**
Django／Spring Boot／Gin は専用のモバイルテンプレートを使い、FastAPI の Vue 画面はレスポンシブレイアウトと折りたたみナビゲーションを使います。

**Q：複数人で同時に使えますか？**
はい、データはアカウントごとに分離されています。ユーザー管理は管理者のみ（`／admin/users/` または該当ページ）。

## 7. 推奨するリズム

- 朝：3 分で MIT とタイムボックスを書く；
- 各タイムボックス終了時：30 秒でチェックと確認；
- 夜：5 分で 4 つのレビュー設問に答える；
- 毎週：固定で 30〜45 分の週次レビュー；
- 毎月：固定で 45〜60 分の月次リファクタ。

1 四半期続けたら、月次の「システム健全性」スコアの推移と週次の「続ける／調整する／やめる」の記録で、システムがあなたのために働いているか判断してください。
