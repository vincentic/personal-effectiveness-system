# 个人效能系统需求规格说明书

> **文档版本**：2026.11.20
> **基线日期**：2026-11-20
> **状态**：现有系统基线
> **依据**：仓库现有页面、API 契约、共享数据库结构及 README；本文记录当前产品范围，不代表所有验收目标均已完成验证。

## 范围基线

- **发现方式**：核对 [`README.md`](../README.md)、[`db/API.md`](../db/API.md)、[`db/schema.sql`](../db/schema.sql)、现有 Vue 页面及 Go、Java、Django、FastAPI 的路由和数据模型。
- **纳入范围**：6 个业务领域——账户与权限、工作台、每日执行、每周复盘、每月重构、多端访问与共享数据。
- **实现形态**：Gin 与 Spring Boot 各有独立的服务端页面版和 REST API 版；Django 提供服务端页面；FastAPI 提供 REST API 并可同源托管 Vue 构建产物；共享 Vue 源码独立位于 [`versions/vue/pms-vue/`](../versions/vue/pms-vue/)。
- **范围边界**：各后端是同一产品的替代实现，不要求在一个部署中同时运行。Django、Gin 页面版和 Spring 页面版不提供与 API 版本相同的 `/api/**` 契约。共享 Vue 当前面向 FastAPI、Gin API 和 Spring API；它不包含用户管理页面。
- **依据强度**：业务字段和 API 行为以仓库契约及代码为基线；性能等未被现有实现证明的数值仅作为待验收目标。

## 用户场景与测试

### 用户故事 1：完成每日执行清单（优先级：P1）

用户需要明确当天最重要的成果，安排可执行的时间盒，并在当天结束时记录结果和阻力。

**独立测试**：以普通账号登录，创建、查看、编辑和删除一个日期的清单，并核对关联时间盒及工作台摘要。

**验收场景**

1. **假设**用户已登录且该日期没有清单，**当**用户提交日期、精力、MIT 和时间盒，**则**系统保存清单并展示于每日记录列表。
2. **假设**清单含多个时间盒，**当**用户修改或勾选时间盒并保存，**则**组块明细与完成进度反映最新记录。
3. **假设**该用户该日期已有清单，**当**用户再次创建同日期清单，**则**系统拒绝重复记录并说明原因。

### 用户故事 2：回顾一周并规划下一周（优先级：P1）

用户需要按工作、学习、身体、关系四个领域回顾事实，整理任务流，并确定下一周优先成果。

**独立测试**：创建周复盘，保存领域状态、任务流、最多三项下周成果及复盘问题，再编辑并删除该记录。

**验收场景**

1. **假设**该用户本周尚无复盘，**当**用户保存周起始日、领域回顾和任务流，**则**记录及明细可在列表和详情中读取。
2. **假设**用户编辑现有复盘并提交明细数组，**当**保存成功，**则**系统展示本次提交的明细，而非残留旧明细。
3. **假设**该用户本周已有复盘，**当**用户重复创建同一周记录，**则**系统拒绝重复记录。

### 用户故事 3：进行每月重构（优先级：P1）

用户需要判断长期投入是否继续、评估系统健康，并记录下一阶段保留、删减和实验的改变。

**独立测试**：创建月度记录，填写价值判断、健康检查，核对均分后完成编辑和删除。

**验收场景**

1. **假设**该用户本月尚无记录，**当**用户填写月份、判断和健康检查，**则**记录被保存并可再次读取。
2. **假设**健康检查包含有效分数，**当**系统展示月度摘要，**则**均分仅根据已填写的 1–5 分计算；无分数时展示为空。
3. **假设**该用户本月已有记录，**当**用户重复创建同一月份记录，**则**系统拒绝重复记录。

### 用户故事 4：查看个人效能概览（优先级：P2）

用户需要从工作台查看当日、本周、本月状态、历史记录数量和近期进展。

**独立测试**：准备不同日期的个人记录，打开工作台并核对当前周期摘要及近期记录。

**验收场景**

1. **假设**用户存在当日、本周或本月记录，**当**用户打开工作台，**则**对应摘要显示正确记录或明确的空状态。
2. **假设**用户有近期每日清单，**当**系统计算组块概览，**则**完成与总数按最近七条每日清单汇总。

### 用户故事 5：安全地跨设备和 API 使用个人数据（优先级：P1）

用户需要在桌面或手机浏览器中使用系统；需要 Vue 的用户可以连接任一兼容 API 后端，而不改变业务数据契约。

**独立测试**：使用共享数据库和兼容 API，分别从 Vue 与 API 读取同一账号记录；使用另一账号尝试访问该记录。

**验收场景**

1. **假设**用户通过 API 登录成功，**当**其请求需要认证的资源，**则**请求在有效凭证下成功，缺失或无效凭证被拒绝。
2. **假设**用户 A 拥有某条记录，**当**用户 B 读取、更新或删除该记录，**则**记录内容不会泄露或被改变。
3. **假设**Vue 配置为连接 FastAPI、Gin API 或 Spring API，**当**用户执行相同的清单操作，**则**输入输出遵循共享 API 契约。
4. **假设**用户使用支持 PC / Mobile 页面切换的服务端页面版，**当**用户选择自动、PC 或 Mobile 模式，**则**偏好在后续页面访问中保持。

### 边界情况

- 重复日期、周起始日或月份不得创建重复主记录。
- 日期、月份、时间、枚举、字符串长度及健康分数不符合约束时，服务端拒绝写入并返回可理解的错误。
- 子表明细数组为空时，更新操作应按契约清空旧明细。
- 访问不存在或不属于当前用户的记录时，不返回该记录的数据。
- 用户表为空时，服务按本地配置初始化首个管理员；已有用户时不得因此重复创建默认账号。
- 未构建 Vue 前端时，FastAPI 页面入口应明确告知如何构建；API 路由仍可用。

## 需求

### 功能需求

- **REQ-001**：系统必须支持账号登录和退出；登录后仅可访问受当前实现权限规则允许的功能。
- **REQ-002**：系统必须按当前账号隔离每日、每周、每月记录及其明细；读取、更新或删除他人记录不得泄露或修改数据。
- **REQ-003**：用户必须能够为一个日期创建和维护每日执行清单，记录睡眠时长、精力、MIT、执行检查、生活维护和晚间复盘。
- **REQ-004**：用户必须能够为每日清单添加、编辑、排序、完成和移除多个时间盒；系统必须根据组块数据计算完成数和完成进度。
- **REQ-005**：系统必须限制同一用户每天最多一条每日清单，并校验日期、精力值、睡眠时长及时间盒字段。
- **REQ-006**：用户必须能够创建和维护每周复盘，记录四个领域的事实与状态、任务流、下周最多三项成果、深度时间、If-Then 计划和复盘问题。
- **REQ-007**：系统必须限制同一用户每周最多一条周复盘；领域不得重复，状态及任务流分栏必须符合允许值。
- **REQ-008**：用户必须能够创建和维护每月重构，记录成果、投入价值判断、机会成本、保留/删减/实验事项、季度校准问题和健康检查。
- **REQ-009**：系统必须限制同一用户每月最多一条月度记录；健康模块不得重复，分数只能为空或 1–5，并提供已评分项目的均分。
- **REQ-010**：用户必须能够查看、创建、编辑和删除其有权访问的日、周、月记录；删除主记录时其明细一并删除。
- **REQ-011**：系统必须提供工作台，展示当前日、周、月记录状态、记录数量、近期记录及最近七条每日清单的时间盒汇总。
- **REQ-012**：管理员必须能够通过对应后端提供的管理界面或 API 查看及创建用户；普通用户不得执行管理员专属操作。共享 Vue 当前不承担用户管理入口。
- **REQ-013**：兼容的 REST API 必须遵循 [`db/API.md`](../db/API.md) 的端点、字段、认证、用户隔离和错误语义；Gin、Spring Boot 与 FastAPI API 版必须能在共享密钥配置一致时互验 HMAC Token。
- **REQ-014**：共享 Vue 必须支持调用 FastAPI、Gin API 和 Spring API，并在 PC 与手机屏幕尺寸下提供工作台、每日、每周、每月和登录流程。
- **REQ-015**：Gin、Spring Boot 和 Django 服务端页面必须提供各自实现的登录保护、CSRF 防护和 PC / Mobile 页面行为；自动模式按设备选择，手动偏好可保持。
- **REQ-016**：实现版本必须遵循共享数据结构及账号归属规则，使一个版本写入的数据可由使用相同数据库的兼容版本读取。
- **REQ-017**：服务端必须验证日期、时间、枚举、长度、唯一周期和分数等输入约束；无效请求不得以成功结果响应。
- **REQ-018**：密码不得以明文持久化；认证凭证缺失、无效或过期时，系统必须阻止受保护资源访问。

### 关键实体

- **用户**：账号名、显示名、凭证摘要和管理权限。
- **每日执行清单**：用户、日期、MIT、精力、检查项和复盘文字；每个用户每天至多一条。
- **时间盒组块**：所属每日清单、输入、关键动作、可验收输出、时间和完成状态。
- **每周复盘**：用户、周起始日、领域事实、任务流、下周成果、计划和复盘问题；每用户每周至多一条。
- **每月重构**：用户、月份、成果与价值判断、改进事项及季度校准；每用户每月至多一条。
- **健康检查**：所属月度重构、健康模块、可选评分及需要的改变。

## 成功标准

以下是本需求基线的验收目标，不是对当前生产性能的声明：

- **SC-001**：对每日、每周、每月三种周期，重复主记录的创建请求均被拒绝；在对应周期内，单账号最多保留一条记录。
- **SC-002**：对跨账号读取、更新和删除的验收用例，未经授权的操作成功率为 **0%**，且原所有者数据保持不变。
- **SC-003**：在共享数据库配置下，三种 API 后端（FastAPI、Gin、Spring Boot）均能完成登录及日/周/月记录的创建、读取、更新和删除契约用例。
- **SC-004**：每项核心业务流程（每日执行、每周复盘、每月重构）均可在其声明支持的客户端中完成新增、编辑、查看和删除。
- **SC-005**：工作台展示的周期摘要、记录计数和最近七条每日清单组块汇总与该账号实际数据一致。
- **SC-006**：代表性新用户可在可用桌面与手机界面找到三项核心流程，且无需复制或重建账号数据即可切换兼容前端/后端组合。

## 假设与边界

- 日期周期按用户所在地日历处理；每周从周一开始。
- “共用数据库”指使用同一份兼容的 v2 表结构和账号数据；具体页面与 API 认证机制可以不同。
- 系统不包含第三方日历同步、团队协作、通知、支付或离线编辑要求。
- 响应时间、并发规模、数据保留期限尚未形成经测量的服务级目标，需在另行定义后验收。
