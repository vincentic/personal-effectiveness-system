# 《Go Gin API + Vue 组合应用》中文口播稿

> **预计时长**：约 18 分钟（含页面与代码演示），不超过 30 分钟
> **组合分支**：`release/go-vue`
> **适用观众**：希望以 Go API 和 Vue SPA 独立部署个人效能系统的开发者

## 00:00–02:00｜开场与组合目标

**画面**：标题、Go API 与 Vue 的两个独立目录、每日/周/月导航。

**旁白**：

大家好，这段视频介绍 Go Gin API 加 Vue 前端的组合。它把业务页面和数据服务分成两个独立进程：Go 负责认证、业务规则和 MySQL 访问，Vue 负责登录、工作台以及每日、每周、每月的交互。

用户的核心需求仍然是把日常执行、周度复盘和月度重构连成闭环。选择这一组合时，Vue 页面不会直接访问数据库，所有业务数据都通过兼容 REST API 的 JSON 请求读写。开发时 Vue 的 Vite 代理把 `/api` 转给 Go；生产环境可以让 Nginx 提供静态页面并反向代理 API。

## 02:00–05:00｜需求与功能流程

**画面**：逐页展示每日、每周、每月表单和工作台。

**旁白**：

每日执行要记录日期、精力、MIT、执行检查、生活维护、晚间复盘，以及一个或多个时间盒。每个时间盒要写清输入、关键动作和可验收输出。这样，“开始工作”不再只是一条模糊任务，而是可以回顾有没有产出。

每周复盘按工作、学习、身体、关系整理事实与状态，清理任务流并定义下周最多三项成果。月度重构则记录目标价值、机会成本、要保留或删减的事情、实验项和健康评分。工作台将当前周期与近期记录放在一起，减少用户在不同页面间寻找信息的成本。

需求还包括账号隔离和周期唯一性。同一账号不能为同一天重复创建每日记录，也不能读取其他账号的清单。验收时，必须用两个不同账号验证所有权边界，而不能只测试正常用户自己的数据。

## 05:00–09:00｜架构与数据通路

**画面**：架构图高亮 Vue → Gin API :8081 → MySQL。

**旁白**：

Go 服务位于 `versions/go/pms-gin-api`，使用 Gin 接收 HTTP 请求，使用 `database/sql` 和项目内 SQL store 操作 MySQL。API 默认端口是 8081，项目目录包含 Go 模块文件、配置、模型、路由、测试和 schema 副本。

Vue 源码位于 `versions/vue/pms-vue`，开发服务器默认端口为 5173。此分支的 Vite 代理默认指向 8081，因此本地可以先启动 Go API，再启动 Vue 页面，不必把数据库开放给浏览器。两端通过 JSON 和 Bearer Token 协作。

用户登录后，API 签发 HMAC Token。之后每个请求都带 `Authorization: Bearer`。Go 服务端从 Token 得到当前用户，并在查询、修改和删除时按用户所有权筛选记录。客户端传入的记录 ID 不能替代服务端的用户校验。

主表保存每日、每周或每月记录；时间盒、领域事实、任务流和健康检查保存在对应明细表。主记录按用户和周期唯一，明细表通过外键关联主记录。写操作通过事务处理主表与明细的变化，失败时避免部分写入。

## 09:00–13:00｜演示核心操作

**画面**：运行 Gin API 和 Vue 开发服务器；演示登录、保存周复盘、编辑明细。

**旁白**：

演示开始先准备 MySQL，按项目示例配置数据库地址、端口、用户和密码，再配置 API_SECRET 与初始管理员信息。生产环境不能使用示例密钥，也不能把 `.env` 上传到 Git。

启动 Go 服务后，在浏览器打开 Vue 页面，使用演示账号登录。先在工作台确认空状态，再新增一条每日计划：写一个 MIT，添加两个时间盒，并为每个时间盒填写明确产出。保存后回到列表，检查日期和完成进度。

接着创建周复盘，填写工作领域事实、一个受阻状态和一条进行中的任务。保存后重新打开记录，修改任务流并保存。这里要注意，提交的明细数组代表完整的新集合；如果把数组改为空，旧明细就会被清除。

最后尝试再次创建同一天的每日记录，页面应该看到清楚的错误提示。演示中不要只展示成功路径，重复周期、未登录请求和跨账号访问同样是产品行为的一部分。

## 13:00–16:00｜验收与发布管理

**画面**：展示 Go 测试、Vue 测试、Vite 构建和验收清单。

**旁白**：

Go 侧可运行 `go test ./...`，重点检查路由、输入校验和请求处理；Vue 侧运行前端测试、类型检查和生产构建。当前组合在本次准备中，Go API 测试通过，Vue 有 5 项 API 客户端测试通过，类型检查和构建也通过。这些结果不等于真实 MySQL 生产验收已完成。

完整验收还应使用共享契约数据执行登录、日周月 CRUD、非法字段、重复周期、空明细和跨用户测试。桌面和手机都要从登录走完整流程。发布记录中应保留分支名、提交号、环境变量、数据库兼容要求、测试结果和已知限制。

## 16:00–18:00｜反馈与扩展

**画面**：展示反馈模板和 Nginx 部署拓扑。

**旁白**：

试用阶段建议收集用户完成一条日计划和一条周复盘时的阻塞点，并记录浏览器、屏幕尺寸、复现步骤和期望结果。反馈渠道属于项目运营流程，不是当前 Vue 页面内置的表单；采集时不要要求用户上传密码、Token 或真实个人数据。

后续可以增加新的 Vue 页面或指标，但要先确认 API 契约和数据库字段，再更新 Go 校验、存储、前端类型与测试。生产环境可以把 Vue 静态资源交给 Nginx，API 只通过反向代理对外提供；数据库只开放给应用网络。以上就是 Go Gin API + Vue 组合的需求、架构、演示和验收重点。
