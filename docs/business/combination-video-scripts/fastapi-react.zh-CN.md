# 《FastAPI + React 同源组合应用》中文口播稿

> **预计时长**：约 18 分钟（含页面与代码演示），不超过 30 分钟
> **组合分支**：`release/fastapi-react`
> **前端包管理**：pnpm

## 00:00–02:00｜开场

**画面**：展示 React 页面、FastAPI 服务和 `/docs`。

**旁白**：

大家好，本片介绍 FastAPI 与 React 的同源组合。FastAPI 提供 REST API，同时托管 React 构建后的静态文件。React 源码仍然是独立的 pnpm 工程，但生产构建会输出到 FastAPI 的 `app/web`。因此浏览器访问一个站点即可加载页面并调用 API。

核心业务仍是每日执行、每周复盘、每月重构。前端负责交互和状态展示，后端负责身份验证、字段校验、用户归属与数据写入。React 的切换不会改变数据库业务结构。

## 02:00–05:00｜需求和功能分析

**画面**：展示三个清单和工作台；高亮 MIT、领域事实和健康评分。

**旁白**：

每日执行帮助用户选择一个 MIT，安排时间盒，记录输入、动作、输出和完成状态。每周复盘按工作、学习、身体和关系回看事实，整理任务流并安排下周成果。每月重构让用户评估价值、机会成本、系统健康和下一步实验。工作台把当前周期状态集中呈现。

这套功能必须同时满足可用性和数据边界：新增后能够读取，编辑后明细准确替换，删除后关联数据清理；用户只能操作自己的记录；非法日期、状态和分数要在服务端被拒绝。移动设备上也要完成主要流程。

## 05:00–09:00｜架构与构建路径

**画面**：展示 `vite.config.ts` 的 `outDir`，再展示 FastAPI 静态目录。

**旁白**：

FastAPI 项目位于 `versions/python/pms-fastapi`，React 项目位于 `versions/react/pms-react`。API 默认监听 8000，React 开发服务器默认 5174，代理目标为 FastAPI。生产构建则将 React 的 `index.html` 和 assets 输出到 FastAPI 的 `app/web`，FastAPI 从根路径提供页面。

后端使用 Pydantic 模型定义请求形状，认证依赖解析 HMAC Bearer Token，PyMySQL 执行数据操作。React 使用 TypeScript 类型和集中式 `api.ts` 调用 REST API，Token 放在浏览器会话存储中；遇到 401 时回到登录状态。

这种同源路径降低了生产 CORS 配置复杂度，但构建顺序变得重要：必须先构建 React，再打包 FastAPI。静态资源的 URL 路径和 API 路由也要分别确认，不能误把 `/api` 请求回退到 React 首页。

## 09:00–13:00｜录屏演示

**画面**：执行 pnpm 安装与构建，启动 FastAPI，演示每日新增和周复盘编辑。

**旁白**：

准备 MySQL 和 Python 环境后安装 FastAPI 依赖，并按 `.env.example` 配置数据库、API_SECRET 和管理员账号。在 React 项目目录执行 `pnpm install --frozen-lockfile`，再执行生产构建。此分支的构建会更新 FastAPI 的静态资源目录。

启动 FastAPI 后打开根路径，确认 React 登录页面加载；随后访问 `/docs`，确认 API 文档仍可访问。登录后新增每日清单，为时间盒填写一个具体输出。保存并刷新页面，检查数据回读。再新增周复盘，写一条领域事实和任务流，编辑后确认替换内容准确。

代码追踪可以从 React 的路由和 View 开始，经 `api.ts` 进入 FastAPI 路由，再看 Pydantic 验证和数据库访问。要额外观察主记录与明细分别写入时的失败行为，确认系统不会把部分成功误报成完整成功。

## 13:00–16:00｜验收和发布

**画面**：展示 React 测试、lint、typecheck、build，以及 FastAPI 健康检查。

**旁白**：

前端自动验收包括 5 项 API 客户端测试、lint、TypeScript 检查和 Vite 构建。本组合还要在构建后启动 FastAPI，验证 `/` 返回 React 页面、assets 可加载、`/api` 路由正常、`/docs` 和 `/health` 不受影响。

后端验收覆盖认证、日周月 CRUD、跨账号访问、重复周期、非法字段和数据库错误。还要记录生产环境的 Python 版本、pnpm 锁文件、构建提交、环境变量来源和回滚步骤。仅有前端构建成功不能替代真实数据库集成验收。

## 16:00–18:00｜反馈和扩展

**画面**：展示反馈收集字段、React 构建产物及可选独立部署图。

**旁白**：

反馈收集建议围绕用户任务，而不是框架偏好。询问用户是否能完成日计划、是否理解周任务流、月度评分是否有帮助，并记录具体阻塞步骤。反馈表不要包含密码、Token 或个人清单原文；系统当前没有内置反馈模块。

未来可以把 React 静态资源拆成独立 CDN 或容器，也可以继续使用 FastAPI 同源托管。无论选择哪种方式，都要复核构建路径、CORS、缓存更新和 SPA 路由。增加业务功能时同步更新类型、API 契约、Pydantic schema、数据库迁移和验收用例。
