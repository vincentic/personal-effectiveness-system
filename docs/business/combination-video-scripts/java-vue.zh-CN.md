# 《Spring Boot API + Vue 组合应用》中文口播稿

> **预计时长**：约 18 分钟（含页面与代码演示），不超过 30 分钟
> **组合分支**：`release/java-vue`
> **适用观众**：使用 Java 17、Spring Boot 与 Vue 的开发、测试和运维人员

## 00:00–02:00｜开场

**画面**：展示 Vue 页面和 Spring Boot API 项目目录。

**旁白**：

大家好，这段视频介绍 Spring Boot REST API 加 Vue 前端的个人效能系统。Vue 负责浏览器中的登录、工作台和日周月清单；Java 服务负责身份验证、业务校验和 MySQL 持久化。它们是两个独立项目，通过 HTTP JSON 契约连接。

用户通过每日执行明确今天的成果，通过每周复盘整理四领域事实和任务流，再通过每月重构决定下一阶段的投入。我们的目标不是展示技术名词，而是解释每个技术组件如何支撑这些用户任务。

## 02:00–05:00｜需求与功能范围

**画面**：展示每日时间盒、每周任务流、月度健康评分。

**旁白**：

每日记录包含日期、睡眠、精力、MIT、检查项、晚间复盘和多个时间盒。周记录包含领域事实、状态、任务流、下周成果和 If-Then 计划。月记录包含价值判断、机会成本、改进事项及健康模块评分。工作台则提供当前周期和近期记录的概览。

除了功能，验收必须覆盖唯一周期和用户归属。同一用户同一天只能有一条每日清单；尝试修改另一个用户的记录时，服务端不能泄露内容。对页面而言，新增、读取、编辑、删除都要成功；对 API 而言，错误请求也必须有可理解、可重复验证的行为。

## 05:00–09:00｜Java 与 Vue 架构

**画面**：高亮 Vue :5173 → Spring API :8080 → MySQL。

**旁白**：

Spring Boot API 位于 `versions/java/pms-springboot-api`，默认端口是 8080。它由 Web Controller 接收请求，安全配置验证 HMAC Token，输入 DTO 表达 JSON 结构，Repository 使用 JdbcTemplate 执行数据库访问。Vue 项目位于 `versions/vue/pms-vue`，默认 Vite 端口是 5173，此组合把开发代理指向 8080。

API 登录成功后，前端持有 Bearer Token，并在后续请求中发送。Spring 端必须由服务端验证签名和有效期，再将身份转换为当前用户。读取和写入记录时，数据访问条件始终包含用户归属，不能把前端提交的 user_id 当成授权证据。

数据库使用共享 schema。周复盘由主记录、领域明细和任务流明细构成。Repository 的事务边界把主表和明细更新作为整体处理，避免发生一半成功、一半失败的状态。这是本组合中需要重点说明和验收的设计决策。

## 09:00–13:00｜用户流程和代码演示

**画面**：启动 Spring API 和 Vue；打开 `WeeklyView.vue`，再定位 API Controller 和 Repository。

**旁白**：

先准备 Java 17、Maven 和 MySQL，配置 `.env` 中的数据库连接、Token 密钥和管理员信息。前端按 Vue 项目锁文件安装依赖。启动 Spring Boot 后，再启动 Vue 开发服务器。

演示登录后创建周复盘：为工作领域写下一项事实，选择状态，添加一条进行中的任务，填写下周成果。保存后从列表重新打开，并修改任务流。回到数据库或详情响应，确认主记录与两类明细一致。再尝试重复创建同一周记录，确认被唯一性规则阻止。

代码追踪从 Vue 的页面状态和 `api.ts` 开始，经过 Spring Controller 的请求 DTO，再到日期、枚举、重复领域和任务流校验，最后进入 Repository。更新流程要额外检查记录归属。Repository 保存成功后再读取完整对象并返回，前端据此刷新历史列表。

## 13:00–16:00｜验收与发布

**画面**：展示 `mvn test`、Vue 测试与构建、API 验收矩阵。

**旁白**：

Java API 可运行 `mvn test`，当前测试套件中的 7 项测试通过；Vue 前端包含 5 项 API 客户端测试，并可执行类型检查和构建。这个结果证明对应测试和构建命令通过，不代表真实 MySQL 的所有集成验收都已完成。

发布前应覆盖登录、日周月 CRUD、字段边界、重复周期、跨账号、空明细和浏览器移动布局。把 API 响应与共享契约逐项核对，特别关注状态码、错误信息和响应字段。记录 JAR 版本、前端构建产物、密钥注入方式和回滚版本。

## 16:00–18:00｜反馈与扩展

**画面**：展示反馈分类和下一版候选事项。

**旁白**：

建议在试点中观察用户如何填写周复盘，统计“理解困难”“字段缺失”“保存失败”和“性能感受”等反馈类别。不要收集敏感记录原文；尽量让用户报告流程和字段问题。反馈渠道由团队选择，目前不是 Vue 或 Spring 的内置模块。

后续可以增加报表或管理员功能，但每个新字段都要走需求确认、数据迁移、DTO 校验、Repository、前端类型和回归测试。不要只改 SQL 或页面中的一侧。以上就是 Spring Boot API 与 Vue 的设计和交付重点。
