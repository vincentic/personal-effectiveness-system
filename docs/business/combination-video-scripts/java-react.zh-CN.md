# 《Spring Boot API + React 组合应用》中文口播稿

> **预计时长**：约 18 分钟（含页面与代码演示），不超过 30 分钟
> **组合分支**：`release/java-react`
> **前端包管理**：pnpm

## 00:00–02:00｜开场

**画面**：展示 React 工作台和 Java API 项目目录。

**旁白**：

大家好，本片讲解 Spring Boot REST API 与 React 前端的组合。Spring Boot 提供可独立部署的 API；React 19 与 TypeScript 提供响应式用户界面。它们通过 JSON 与 Bearer Token 交互，数据库仍由 Java 服务端访问。

产品围绕每日执行、每周复盘和每月重构。用户既可以安排当天时间盒，也可以回顾一周的四个生活领域，再通过月度记录复核目标和系统健康。前端框架更换不应改变这些业务含义或 API 数据结构。

## 02:00–05:00｜用户需求

**画面**：展示三类清单和工作台。

**旁白**：

核心需求可以归纳为四点：第一，快速记录日、周、月数据；第二，支持主记录和重复明细的新增、编辑、删除；第三，工作台提供周期摘要；第四，数据始终按账号隔离。

每日时间盒需要可验收的输出；周复盘需要领域事实和任务流；月度重构需要价值判断、改进项和健康分数。对于用户来说，空状态、重复记录和权限错误都需要清楚提示。这些要求必须成为验收用例，而不是只在需求文档中存在。

## 05:00–09:00｜架构与认证

**画面**：高亮 React :5174 → Spring API :8080 → MySQL。

**旁白**：

Java API 位于 `versions/java/pms-springboot-api`，默认监听 8080。Controller 接收请求，DTO 定义输入，认证模块验证 HMAC Token，Repository 使用 JdbcTemplate 访问 MySQL。React 工程位于 `versions/react/pms-react`，pnpm 锁文件固定依赖；Vite 开发服务器默认端口 5174，代理转向 8080。

登录后，React API 客户端将 Token 保存在浏览器会话中，并为受保护的请求添加 Bearer 头。收到 401 时清除会话并返回登录流程。服务端根据验证后的 Token 获取当前用户，而不是相信客户端传来的所有者字段。

数据层对周期主记录设置唯一性，对明细设置外键。Java Repository 通过事务保存主记录和替换子表集合。这样当明细插入失败时，主记录也能回滚。这个事务保障需要通过故障用例确认，而不仅是查看代码。

## 09:00–13:00｜应用演示

**画面**：运行 Java API 与 React 页面，演示日清单和月度记录。

**旁白**：

准备好 Java、Maven 和 MySQL 后，配置后端环境。前端在 React 项目目录执行 `pnpm install --frozen-lockfile`，然后启动 Vite 开发服务器。登录后先检查工作台，再创建每日清单，添加两个时间盒并保存。

继续进入月度页面，填写本月成果、价值判断和机会成本，为两个健康模块打分。保存后刷新，再次打开记录，确认数值和文本都已持久化。编辑时将其中一个明细删除并保存，确认旧明细确实被替换。

代码路径从 React `App.tsx` 的认证和导航，到对应 View 的表单，再到 `api.ts` 的请求封装。后端从 Spring Controller 到输入 DTO、认证上下文、校验和 Repository。发生错误时，前端要显示可理解信息，不能把失败伪装成保存成功。

## 13:00–16:00｜验收管理

**画面**：展示 React 5 项 API 测试、lint/typecheck/build 和 Maven 测试。

**旁白**：

React 侧验收包含 5 项 API 客户端测试、ESLint、TypeScript 检查和 Vite 构建；后端使用 `mvn test`，当前测试套件 7 项通过。除此之外，还要在共享数据库环境验证 CRUD、跨账号、重复周期、无效字段和事务回滚。

浏览器验收需覆盖桌面和手机屏宽。版本验收应分别记录 Java 后端和 React 前端的构建结果，不要因为 API 测试通过就推断 UI 也通过。反过来，前端 mock 测试通过也不能证明真实 API 的认证和数据库行为正确。

## 16:00–18:00｜反馈与扩展

**画面**：展示 issue 模板字段和后续扩展路径。

**旁白**：

用户反馈建议记录操作步骤、设备、组合版本、期望结果和实际结果，并按数据正确性、权限、安全、易用性和性能分类。不要在截图或日志中包含 Token、密码或真实清单内容。当前没有内置反馈入口，需由项目团队用受控渠道接收。

未来增加图表、用户管理或通知前，应先评估新的权限和数据边界。React 类型、Java DTO、数据库迁移、接口文档和测试要同步演进。以上就是 Spring Boot 与 React 组合的核心讲解。
