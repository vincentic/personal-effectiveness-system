# 《Go Gin API + React 组合应用》中文口播稿

> **预计时长**：约 18 分钟（含页面与代码演示），不超过 30 分钟
> **组合分支**：`release/go-react`
> **前端包管理**：pnpm

## 00:00–02:00｜开场与组合目标

**画面**：展示 React 工作台、日周月导航及 Go API 目录。

**旁白**：

大家好，本片介绍 Go Gin API 与 React 前端的组合。它面向希望使用 Go 提供 REST 服务、使用 React 构建独立单页应用的团队。Go 处理认证、业务规则和数据库访问；React 负责页面状态、表单与导航。两端通过共享 API 契约连接。

产品主线是每日执行、每周复盘和每月重构。用户可以在桌面或手机浏览器登录，记录 MIT、时间盒、领域事实、任务流、月度目标和系统健康状态。React 与 Vue 提供相同的核心流程，但分别维护自己的组件和 API 客户端。

## 02:00–05:00｜需求与用户流程

**画面**：展示登录、工作台、每日页面、周复盘和月重构页面。

**旁白**：

需求首先落在“可执行”。每日清单将一个重要成果拆成有输入、有关键动作、有验收输出的时间盒，并在晚上记录实际完成和阻力。周复盘回看工作、学习、身体、关系四个领域，将任务分成待办、进行中、已完成和退出等状态，再安排下一周的优先成果。月度重构帮助用户判断是否继续当前投入，并记录保留、删减和实验。

工作台要显示当前周期摘要；登录和退出要清晰；表单要支持新增、编辑、删除和明细维护。系统还必须限制重复周期，并确保一个账号无法访问另一个账号的记录。我们把这些条件写成验收场景，而不是只用“页面正常”作为通过标准。

## 05:00–09:00｜系统设计与组件关系

**画面**：架构图高亮 React → Gin API :8081 → MySQL；再切换到 Vite 配置。

**旁白**：

后端在 `versions/go/pms-gin-api`，前端在 `versions/react/pms-react`。Go API 默认监听 8081，React 的 Vite 开发服务器默认监听 5174，并将 `/api` 与 `/health` 代理到所选 API。此分支已把默认代理目标设为 8081。

React 使用 TypeScript 描述用户、日周月记录和明细结构；API 客户端集中处理请求头、Token 和错误响应。Token 保存在当前浏览器会话的 sessionStorage，401 响应会回到登录流程。它不是数据库凭证，也不应写入页面截图或日志。

Gin API 通过 HMAC Token 确认当前用户，再由模型和 SQL store 读取、插入或更新数据。用户归属由服务端上下文决定，更新和删除必须同时检查记录 ID 和当前用户。MySQL 中主记录按用户和周期唯一，时间盒、领域事实、任务流等通过外键关联。

本组合的优势是前端与后端可独立构建和发布。代价是部署时要正确配置 API 地址、CORS 和代理规则。开发代理可减少本机跨域问题，但它不会自动替代生产环境的 HTTPS、反向代理和安全配置。

## 09:00–13:00｜页面演示与代码入口

**画面**：pnpm 安装、启动后端和前端；演示新建日计划和编辑月度记录。

**旁白**：

先准备 MySQL 和 Go 环境，复制项目示例环境文件并配置数据库连接、API_SECRET 和管理员账号。然后在 React 项目目录执行 `pnpm install --frozen-lockfile`，用冻结锁文件安装相同依赖。开发时分别启动 Go API 和 React Vite 服务。

登录后先打开工作台，再进入每日执行。创建一个 MIT，增加一个时间盒，写下可检查的输出并保存。重新打开页面，确认该记录被读回。然后进入周复盘，添加领域事实和任务流，编辑后确认明细完全符合新的提交内容。最后查看月度页面，给两个健康模块评分，确认系统只对有效评分计算平均数。

代码阅读时从 `src/App.tsx` 看应用入口和导航，再看对应视图中的表单状态，最后追踪 `src/api.ts` 中的请求。服务端则从 Gin router、认证中间件、请求模型和 SQL store 往下看。这样可以沿着用户点击一路追到数据库，而不是只看单个组件。

## 13:00–16:00｜验收管理

**画面**：展示 React 测试与构建输出、Go 测试结果、跨账号测试表。

**旁白**：

前端验收包括 5 项 API 客户端测试、ESLint、TypeScript 检查和 Vite 生产构建；Go API 使用 `go test ./...`。本次准备中的 Go 测试和 React 5 项测试、lint、类型检查及构建均通过。真实数据库集成和生产环境安全验收仍需在目标环境执行。

建议把验收分为四层：页面操作，API 契约，数据库约束，部署冒烟。数据用两个测试账号，覆盖成功、无权限、重复周期、非法枚举和空明细。每条需求都要留下结果和证据链接。发布时记录组合分支与 tag，避免把 Vue 版本的测试结果误认为 React 版本的验收结果。

## 16:00–18:00｜反馈与下一步

**画面**：反馈模板、React 构建产物与 Nginx/API 拓扑。

**旁白**：

试用者反馈应描述具体任务和卡点，比如“手机上编辑时间盒时找不到保存按钮”，而不只是“体验不好”。记录版本、设备、步骤、预期和实际结果，并去除账号、Token 和个人记录。当前应用没有内置反馈收集功能，需要通过项目指定的 issue 或问卷流程管理。

扩展 React 页面时，要同时核对 TypeScript 类型、API 行为和跨端布局；扩展 Go API 时，要更新校验、数据访问、契约测试和安全边界。完成以后再通过同一验收清单回归。以上就是 Go API 与 React 的组合路径。
